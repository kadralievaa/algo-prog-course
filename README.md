1. В Python программа выполняется построчно, интерпретатор читает строку и сразу ее выполняет. Поэтому он заметит ошибку только тогда, когда до нее дойдет. Если строка с ошибкой никогда не выполнится, то программа даже не узнает о ней. В C# по другому. Сначала компилятор читает весь код целиком и если где то есть ошибка, то он откажется собирать программу и она не запуститься. Даже если ошибка будет в строке, которая не будет использоваться.
2. Команда "dotnet run" собирает проект, то есть компилирует файлы и запускает уже собранную программу.
3. В "-bin/" компилятор складывает готовую программу. А "-obj/" это промежуточные служебные файлы, которые нужны во время сборки. Они не являются исходным кодом, если удалить эти папки, то они создадутся заново при написании "dotnet run".
4. "git commit" сохраняет снимок изменений на компьютере. На GitHub его нет. "git push" отправляет эти коммиты на GitHub.
5. Конкатенация через "+" склеивает строки. Интерполяция через " $"nnn" " подставляет значение переменных в текст. Мне больше нравиться интерполяция, потому что можно сразу различить, где текст, а где переменные.
6. Если оба числа записаны через int, то и результат будет представлен в виде int, дробная часть отбрасывается, не округляется. Исправить можно так, превратить хотя бы одно число в double, с помощью (double).
7. const это переменная, которой значение задается только один раз и потом его нельзя изменить. Если дать новое значение, то компилятор выдаст ошибку. Например, у меня в коде есть "const int MonthInSeptember = 4;" так как в семестре всегда 4 месяца.
8. Top-level statements это когда код можно писать сразу. Так получается короче и понятнее. Раньше надо было проделать большой путь чтобы начать писать код, а сейчас можно просто "Console.WriteLine("Hello, Word!");" Компилятор все равно превратит это в класс c Main, но писать самой мне это не нужно.
